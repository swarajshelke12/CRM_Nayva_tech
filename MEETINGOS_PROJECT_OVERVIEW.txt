1. EXECUTIVE SUMMARY & PURPOSE
--------------------------------------------------------------------------------
This project is a high-polish, lightweight, client-facing web prototype called
"MeetingOS", designed for an AI automation agency: NAVYA TECH SOLUTIONS
(Website: https://www.navyatech.co.in/).

The primary goal of this application is to serve as a proof-of-concept client 
portal that wraps around a single, powerful n8n backend automation: 
"AI Meeting Preparation & WhatsApp Dispatch".

Key Design Principles:
- The client NEVER sees or touches n8n nodes, JSON webhooks, or VPS servers.
- The client experiences a sleek, intuitive, minimalist B2B SaaS interface.
- Zero unnecessary complexity: No database, no auth walls, no real OAuth,
  no real backend API calls. Everything runs cleanly via local state and 
  realistic mock data.
- Built strictly with 4 core screens:
  1. Dashboard
  2. Meetings
  3. Meeting Preparation
  4. Connections / Setup


2. END-TO-END SYSTEM WORKFLOW (HOW IT WORKS IN PRACTICE)
--------------------------------------------------------------------------------
From a business perspective, the flow between the client and Navya Tech is:

Step A: Client Setup (Connections / Setup Screen)
  - The client enters their Google Calendar account email, recipient WhatsApp 
    mobile number, Apify token (for LinkedIn scraping), and AI API key.
  - All credential cards are explicitly labeled "Waiting for configuration".
  - A clear callout informs the client that the Navya Tech engineering team 
    manually reviews and configures these credentials directly inside the 
    agency's private n8n workflow.

Step B: Autonomous n8n Workflow Execution (Agency Backend)
  - 1 hour before any scheduled Google Calendar call, the n8n automation triggers.
  - n8n identifies the attendee's name and email address.
  - n8n calls Apify to extract the attendee's recent LinkedIn career history.
  - n8n searches past Gmail correspondence to summarize conversation history.
  - An LLM (OpenAI / Anthropic) synthesizes:
      * Strategic Meeting Objective
      * Distilled Email Summary
      * LinkedIn / OSINT Insights
      * 4 Actionable Talking Points
  - n8n pushes a formatted briefing card directly to the client's WhatsApp.

Step C: Client Portal Experience (This React Prototype)
  - The client opens this MeetingOS portal.
  - They see their upcoming calls, track preparation progress, inspect full 
    intelligence dossiers, copy talking points with one click, or review 
    the WhatsApp dispatch log.


3. SCREEN-BY-SCREEN BREAKDOWN
--------------------------------------------------------------------------------

SCREEN 1: DASHBOARD (src/components/views/DashboardView.tsx)
  - Header Banner: Confirms "Automation Active" for "AI Meeting Preparation".
  - Key Metrics Row (3 cards):
      * Upcoming Meetings (4 scheduled this week)
      * Briefs Prepared (2 completed dossiers ready)
      * Est. Time Saved (~6.5 hours of manual research eliminated)
  - Upcoming Calendar Calls Table:
      * Shows upcoming meetings, attendee avatars, company, and date/time.
      * Shows preparation status pills ('Prepared', 'In Progress', 'Scheduled').
      * Direct "View Brief" button that jumps immediately to Screen 3.
  - Latest WhatsApp Dispatch Card:
      * Displays a preview of the most recent briefing card delivered to the 
        client's phone (+1 555 234-8901) 1 hour before the call.

SCREEN 2: MEETINGS (src/components/views/MeetingsView.tsx)
  - Overview list of all scheduled meetings pulled from the calendar.
  - Real-time search filter (searches attendee name, company, or meeting title).
  - Status Filter Tabs: [All], [Prepared], [In Progress], [Scheduled].
  - Clean table showing:
      * Attendee avatar, name, executive title, company
      * Date, time slot, and meeting platform (Google Meet / Zoom)
      * Status pill badge (emerald for Prepared, amber for In Progress, zinc for Scheduled)
      * "View Preparation" / "Details" action button.

SCREEN 3: MEETING PREPARATION (src/components/views/MeetingPrepView.tsx)
  - Top Switcher: Quick pills to switch between attendees (Sarah, Jonathan, Elena, Michael).
  - Attendee Profile Card: Avatar, full name, title, company, verified email, and call time.
  - 4 Structured Intelligence Dossier Cards:
      1. Meeting Objective & Overview: Strategic context, high-intent goals, and background.
      2. Email Correspondence Summary: Key takeaways distilled from previous email threads.
      3. LinkedIn & Background Insights: Professional trajectory, recent posts, priorities.
      4. Recommended Talking Points: Numbered list of high-impact conversation drivers.
  - "Copy Brief" Button: Copies the entire structured dossier to the clipboard in 1 click.

SCREEN 4: CONNECTIONS / SETUP (src/components/views/ConnectionsView.tsx)
  - Agency Notice: "The Navya Tech Solutions team manually configures and connects these 
    credentials directly inside your private n8n automation. Once submitted, your automation 
    will be provisioned."
  - 4 Credential Cards, each badged with "Waiting for configuration":
      1. Google Calendar Account (Primary work email)
      2. WhatsApp Delivery Handset (Phone number receiving mobile briefs)
      3. Apify API Token (For attendee LinkedIn enrichment)
      4. AI Model Provider Key (OpenAI / Anthropic API Key)
  - Security masked inputs with eye icon toggle (show/hide).
  - "Submit Credentials to Navya Tech" Button: Simulates client submission and displays 
    an immediate green confirmation banner with a 24-hour setup guarantee.

--- FILE: src/context/AppContext.tsx ---
import React, { createContext, useContext, useState } from 'react';
import type { Screen, Meeting, ConnectionSetup } from '../types';
import { initialMeetings, initialConnectionSetup } from '../data/mockData';

interface AppContextType {
  currentScreen: Screen;
  setCurrentScreen: (screen: Screen) => void;
  selectedMeetingId: string;
  setSelectedMeetingId: (id: string) => void;
  meetings: Meeting[];
  connections: ConnectionSetup;
  updateConnections: (updates: Partial<ConnectionSetup>) => void;
  viewMeetingPrep: (meetingId: string) => void;
}

const AppContext = createContext<AppContextType | undefined>(undefined);

export const AppProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
  const [currentScreen, setCurrentScreen] = useState<Screen>('dashboard');
  const [selectedMeetingId, setSelectedMeetingId] = useState<string>('meet-01');
  const [meetings] = useState<Meeting[]>(initialMeetings);
  const [connections, setConnections] = useState<ConnectionSetup>(initialConnectionSetup);

  const updateConnections = (updates: Partial<ConnectionSetup>) => {
    setConnections(prev => ({
      ...prev,
      ...updates,
      status: 'Waiting for configuration',
      lastSubmitted: 'Submitted just now — queued for Navya Tech team setup'
    }));
  };

  const viewMeetingPrep = (meetingId: string) => {
    setSelectedMeetingId(meetingId);
    setCurrentScreen('preparation');
  };

  return (
    <AppContext.Provider
      value={{
        currentScreen,
        setCurrentScreen,
        selectedMeetingId,
        setSelectedMeetingId,
        meetings,
        connections,
        updateConnections,
        viewMeetingPrep
      }}
    >
      {children}
    </AppContext.Provider>
  );
};

export const useApp = (): AppContextType => {
  const context = useContext(AppContext);
  if (!context) throw new Error('useApp must be used within an AppProvider');
  return context;
};


--- FILE: src/App.tsx ---
import React, { useState } from 'react';
import { AppProvider, useApp } from './context/AppContext';
import { Sidebar } from './components/layout/Sidebar';
import { TopHeader } from './components/layout/TopHeader';
import { DashboardView } from './components/views/DashboardView';
import { MeetingsView } from './components/views/MeetingsView';
import { MeetingPrepView } from './components/views/MeetingPrepView';
import { ConnectionsView } from './components/views/ConnectionsView';
import { ExternalLink } from 'lucide-react';

const MainLayout: React.FC = () => {
  const { currentScreen } = useApp();
  const [mobileOpen, setMobileOpen] = useState(false);

  const renderActiveScreen = () => {
    switch (currentScreen) {
      case 'meetings': return <MeetingsView />;
      case 'preparation': return <MeetingPrepView />;
      case 'connections': return <ConnectionsView />;
      case 'dashboard':
      default: return <DashboardView />;
    }
  };

  return (
    <div className="min-h-screen bg-[#09090b] text-zinc-100 flex flex-col font-sans">
      <Sidebar mobileOpen={mobileOpen} setMobileOpen={setMobileOpen} />
      <div className="lg:pl-64 flex-1 flex flex-col min-w-0">
        <TopHeader onOpenMobile={() => setMobileOpen(true)} />
        <main className="flex-1 p-4 sm:p-6 max-w-6xl w-full mx-auto">
          {renderActiveScreen()}
        </main>
        <footer className="border-t border-zinc-850 px-4 sm:px-6 py-3.5 bg-zinc-950 text-xs text-zinc-500">
          <div className="max-w-6xl mx-auto flex flex-col sm:flex-row items-center justify-between gap-3">
            <div className="flex items-center gap-2">
              <span className="font-semibold text-zinc-300">MeetingOS</span>
              <span>·</span>
              <span className="text-zinc-400">AI Meeting Preparation</span>
              <span>·</span>
              <span>Navya Tech Solutions</span>
            </div>
            <a href="https://www.navyatech.co.in/" target="_blank" rel="noopener noreferrer" className="text-zinc-400 hover:text-zinc-200 flex items-center gap-1">
              <span>navyatech.co.in</span>
              <ExternalLink className="w-3 h-3" />
            </a>
          </div>
        </footer>
      </div>
    </div>
  );
};

export function App() {
  return (
    <AppProvider>
      <MainLayout />
    </AppProvider>
  );
}

export default App;

3. Production build test:
   npm run build
