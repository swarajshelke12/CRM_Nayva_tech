# MeetPrep CRM — AI-Powered Meeting Preparation

> **Navya Tech Solutions** | Client Automation Portal

A premium, production-ready CRM dashboard that powers AI-driven pre-meeting intelligence briefings. Built with React + TypeScript + Vite, designed for clients using **n8n workflow automation** in the background.

---

## ✨ Features

| Feature | Description |
|---|---|
| **Dashboard** | Real-time overview of upcoming meetings, workflow health, and automation status |
| **Meeting Cards** | Auto-populated from Google Calendar via n8n with attendee details |
| **AI Meeting Prep** | Briefing summaries generated by GPT-4o — email recaps, LinkedIn insights, talking points |
| **Credentials Portal** | Secure credential entry with **24-hour auto-purge** — credentials are never stored permanently |
| **User Guide** | Interactive "How It Works" modal for non-technical users |
| **Validation** | Format and length validation on all API keys (prefix, suffix, min/max characters) |

### 🔒 Security Model

- Credentials are stored in **browser localStorage only** — no backend database
- **24-hour auto-purge**: credentials are permanently wiped from browser memory after submission
- After 24 hours, the portal shows a locked state — new credentials must be generated from each provider
- Credentials are **hidden by default** after submission (OpenAI-style) with an explicit **Unlock & View** button

## 🚀 Quick Start

### Prerequisites

- [Node.js](https://nodejs.org/) **v18+** (LTS recommended)
- [npm](https://www.npmjs.com/) (comes with Node.js)

### 1. Clone the repository

```bash
git clone https://github.com/<your-org>/nayva-meetprep-crm.git
cd nayva-meetprep-crm
```

### 2. Install dependencies

```bash
npm install
```

### 3. Configure environment (optional)

Copy the example env file and fill in your n8n webhook details:

```bash
cp .env.example .env
```

Edit `.env`:

```env
# n8n webhook trigger URL (from your n8n Webhook Node)
VITE_N8N_WEBHOOK_URL=https://n8n.yourdomain.com/webhook/meeting-os-trigger

# Optional auth token for your webhook
VITE_N8N_AUTH_TOKEN=your-secret-token
```

### 4. Start development server

```bash
npm run dev
```

The app will be available at `http://localhost:5173/` (or the next available port).

### 5. Build for production

```bash
npm run build
```

The production bundle is output to the `dist/` folder. You can serve it with:

```bash
npm run preview
```

## 🔗 n8n Workflow Integration

This CRM is the **frontend portal** for an n8n automation workflow that runs in the background:

1. **Trigger**: n8n checks Google Calendar every hour for upcoming meetings
2. **Email Extraction**: Reads recent email correspondence with attendees via Gmail API
3. **LinkedIn Research**: Scrapes attendee LinkedIn profiles via Apify
4. **AI Briefing**: GPT-4o generates meeting intelligence briefings
5. **Delivery**: Sends the briefing to your WhatsApp via Meta Business API

The workflow JSON is included in the `actual_workflow/` directory — import it into your n8n instance.

### Required Credentials (entered via the CRM portal)

| Credential | Provider | Where to Get It |
|---|---|---|
| Google Client ID + Secret | Google Cloud Console | APIs & Services → Credentials → OAuth 2.0 |
| OpenAI API Key | platform.openai.com | API Keys section |
| Apify API Key | console.apify.com | Settings → Integrations |
| WhatsApp Business ID + Token | Meta Business Manager | System Users → Generate Token |

## 🛠️ For Developers — Extending the CRM

### Adding Authentication

The CRM currently has **no authentication** — it's designed as a single-tenant client portal. To add auth:

1. **Supabase Auth** (dependency already included):
   - `@supabase/supabase-js` is in `package.json`
   - Create auth components in `src/components/auth/`
   - Wrap `<AppProvider>` with an auth guard in `App.tsx`

2. **Custom Auth**:
   - Add your auth provider in `src/services/`
   - Create login/signup screens in `src/components/auth/`
   - Protect routes in `App.tsx`

### Adding a Backend Database

Currently, credentials are stored in browser `localStorage` with a 24-hour auto-purge. To add persistent storage:

1. Create a backend API (Supabase, Firebase, or custom)
2. Update `AppContext.tsx` to call your API instead of `localStorage`
3. Add API service files in `src/services/`

### Customising the 24-Hour Lock Duration

Edit the `LOCK_DURATION_MS` constant in [`src/context/AppContext.tsx`](src/context/AppContext.tsx):

```typescript
// Current: 24 hours
export const LOCK_DURATION_MS = 24 * 60 * 60 * 1000;

// Example: 48 hours
export const LOCK_DURATION_MS = 48 * 60 * 60 * 1000;

// Example: 30 seconds (for testing)
export const LOCK_DURATION_MS = 30 * 1000;
```
